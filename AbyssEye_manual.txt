# AbyssEye 使い方マニュアル

対象ブランチ: `AbyssEye-Neo`

## 1. このソフトでできること

AbyssEye は、TIFF 画像やリアルタイム取得画像をもとに、ROI 抽出、推論、DeepScan による確認、手動ラベル修正、細胞数集計、再学習用データの準備を行うためのツールです。

主な用途は次の 3 つです。

- 保存済み画像をプロジェクト単位で整理して処理する
- 顕微鏡などから送られる最新画像をリアルタイムで確認し、そのまま保存・修正する
- 手動修正済み ROI を学習用データとして蓄積し、再学習に回す

## 2. 起動方法

### 2-1. 初回セットアップ

#### バックエンド

```bash
python3.11 -m venv venv
source venv/bin/activate
pip install -r backend/requirements.txt
```

#### フロントエンド

```bash
cd frontend
npm install
```

### 2-2. 起動

#### バックエンド

仮想環境を有効化済みのターミナルで実行します。

```bash
python backend/main.py
```

#### フロントエンド

別ターミナルで実行します。

```bash
cd frontend
npm run dev
```

起動後、通常は次を開きます。

- フロントエンド: [http://localhost:3000](http://localhost:3000)
- Swagger / API: [http://localhost:8000/api/v1/docs](http://localhost:8000/api/v1/docs)

トップ画面で `バックエンドAPIが利用可能です` と表示されていれば、基本的な接続は正常です。

### 2-3. 再起動だけしたいとき

依存関係の入れ直しをせず、再起動だけしたい場合は次だけで大丈夫です。

#### バックエンド

```bash
python backend/main.py
```

#### フロントエンド

```bash
cd frontend
npm run dev
```

## 3. ホーム画面

ホーム画面には次の 4 つの入口があります。

- `データベース`
  プロジェクトを作成して画像を整理し、画像リストやリアルタイムエンジンへ進みます。
- `モデル選択`
  使用する推論モデルの確認、アップロード、切り替えを行います。
- `再学習`
  再学習に使うプロジェクトまたは保存済み ZIP を選びます。
- `Swagger`
  バックエンド API の一覧を確認し、その場で API を実行できます。

## 4. モデル選択

推論を使う場合は、先にモデルを選択してください。

### 手順

1. ホーム画面で `モデル選択` を開きます。
2. 必要に応じてモデルをアップロードします。
3. 使いたいモデルを `アクティブ化` します。

### 補足

- アクティブモデルは、データベース処理、リアルタイムエンジン、DeepScan の推論に使われます。
- 再学習ページでは、現在の対象モデルとデータセット内の `ai_model_name` の不一致が警告表示されます。

## 5. データベースの使い方

### 5-1. プロジェクトを作成する

1. ホーム画面で `データベース` を開きます。
2. `プロジェクト名` を入力します。
3. `プロジェクトを保存` を押します。
4. 一覧の `開く` を押してプロジェクト詳細へ進みます。

### 5-2. プロジェクト詳細画面

プロジェクト詳細では、用途ごとに次の 2 系統で使います。

- `リアルタイムエンジン`
  観察しながら 1 枚ずつ保存・破棄・修正する用途
- `アップロード`
  保存済み画像を後からまとめて処理する用途

### 5-3. アップロード

プロジェクト詳細では次の 2 種類をアップロードできます。

- `画像`
  単一画像を追加します。
- `同視野画像フォルダ`
  同じ視野の複数画像ファイルを追加します。

### 5-4. 画像リスト

画像リストでは次の操作ができます。

- `ROI抽出&推論`
  ROI 抽出と推論を実行します。
- `DeepScan`
  ROI 抽出と推論が終わった画像を詳細確認します。
- `保存`
  対象画像を含むプロジェクトデータを保存します。
- `削除`
  選択式で画像を削除します。

画像リストでは、次の情報も確認できます。

- `ROI変更数`
  manual label の変更が入った ROI 数
- `ROI追加数`
  手動追加 ROI 数
- `種類`
  `リアルタイム` または `アップロード`

### 5-5. 同視野フォルダリスト

同視野フォルダリストでは次の操作ができます。

- `一覧`
  フォルダ内の画像一覧を開きます。
- `マージ画像作成`
  マージ画像を作成し、画像リスト側へ追加します。
- `削除`
  選択式でフォルダを削除します。

補足:

- マージ画像は同視野フォルダ内には残らず、画像リスト側へ追加されます。
- 作成済みのものは `生成済` と表示されます。

### 5-6. 同視野フォルダ内画像一覧

`一覧` を開くと、そのフォルダ内画像ごとの一覧が表示されます。

主な操作:

- `ROI抽出&推論`
- `DeepScan`
- `保存`

DeepScan は、単一画像と同じく ROI 抽出と推論が終わるまでは開けません。

### 5-7. セルカウント結果

単一画像の推論がそろったら `セルカウント` を実行できます。

結果画面では次の操作ができます。

- 再読み込み
- CSV 出力
- PDF 出力

## 6. リアルタイムエンジンの使い方

### 6-1. 開き方

1. ホーム画面で `データベース` を開きます。
2. プロジェクトを作成または選択します。
3. プロジェクト詳細画面で `リアルタイムエンジン` を押します。

### 6-2. 監視用スクリプトを作る

リアルタイムエンジン画面では、監視フォルダを設定して監視スクリプトをダウンロードできます。

#### Windows

- `.ps1` をダウンロードして実行します。

#### macOS

- `.command` をダウンロードして実行します。

### 6-3. 基本の流れ

リアルタイムエンジンでは、新しい画像が来ても自動で次々切り替えず、保存または破棄をきっかけに次の画像へ進みます。

主な流れ:

1. 新しい TIFF が待機列へ入る
2. 現在画像を確認する
3. 必要なら manual label や手動 ROI を修正する
4. `保存` または `破棄` を押す
5. 次の画像へ進む

### 6-4. 主な操作

- `保存`
  現在画像をプロジェクトへ保存します。
- `破棄`
  現在画像を保存せずに次へ進みます。確認ダイアログが出ます。
- `同視野画像ファイルとして保存`
  同じ視野の複数画像を同一フォルダ・同一 DB として保存します。
- `サンプル名`
  保存名の番号に使います。

### 6-5. 表示切替

- 画像表示: `Raw / Normalized / Jet / Optical Boost`
- ラベル基準: `AI / Manual`
- `Deep Scan`
  ROI 枠や検出状況を全体画像へ重ねて表示します。

### 6-6. 手動修正

- `手動ROI追加`
  ON にして画像をクリックすると 48x48 ROI を追加します。
- `手動ROI削除`
  手動追加 ROI のみ削除できます。
- `Manual Label`
  ROI を選択して 0 / 1 / 2 / 3 / ラベルなし を設定します。

### 6-7. 待機画像数

- 待機画像は最大 10 枚です。
- 10 枚を超えると、古い待機画像から自動で破棄されます。

## 7. DeepScan の使い方

DeepScan は、保存済み画像やリアルタイム画像に対して ROI と推論結果を詳しく確認する画面です。

### 主な機能

- 全体画像上で ROI 枠を確認
- `AI / Manual` のラベル基準切替
- 手動 ROI の追加 / 削除
- manual label の更新
- 前後画像への移動
- ROI 拡大プレビューの確認

### ROI プレビュー

- ROI をクリックすると拡大プレビューが表示されます。
- プレビューは浮遊表示で、ドラッグ移動できます。
- 必要に応じてサイズ変更や埋め込み切替ができます。

## 8. 再学習の使い方

### 8-1. 入り方

1. ホーム画面で `再学習` を押します。
2. パスワード `CORE` を入力して `送信` を押します。

### 8-2. できること

- 再学習に使う既存プロジェクトを選ぶ
- 保存済み ZIP をアップロードする
- 現在の対象モデルを確認する
- データセット内の `ai_model_name` と現在モデルの不一致を確認する

### 8-3. プロジェクト保存 ZIP に含まれるもの

プロジェクト保存 ZIP には再学習用データが含まれます。

主な内容:

- `_training_dataset/labels.csv`
- `_training_dataset/class0/*.png`
- `_training_dataset/class1/*.png`
- `_training_dataset/class2/*.png`
- `_training_dataset/class3/*.png`

対象は `manual label` が付いた ROI です。

## 9. Swagger の使い方

Swagger ではバックエンド API の一覧を確認し、その場で API を実行できます。

### 開き方

1. ホーム画面で `Swagger` を押します。
2. Swagger ページ内で API 一覧を確認します。
3. 必要なら `別タブで開く` で直接 docs を開きます。

### よく使う用途

- API の動作確認
- `dev/git/pull` などの開発用 API 実行
- モデル関連 API や realtime API の確認

## 10. クラス番号の意味

- `0` = 単一細胞
- `1` = 複数細胞
- `2` = ピンぼけ
- `3` = 非細胞粒子

manual label を付けると、AI 推論より手動ラベルが優先されます。

## 11. 典型的な運用例

### 11-1. 保存済み画像を処理する場合

1. `モデル選択` でモデルをアクティブ化する
2. `データベース` でプロジェクトを作る
3. 画像または同視野画像フォルダをアップロードする
4. `ROI抽出&推論` を実行する
5. 必要に応じて `DeepScan` で manual label や ROI を修正する
6. 必要ならセルカウント結果を出力する

### 11-2. リアルタイム取得画像を処理する場合

1. `モデル選択` でモデルをアクティブ化する
2. `データベース` でプロジェクトを開く
3. `リアルタイムエンジン` へ進む
4. 監視フォルダを設定し、監視スクリプトを実行する
5. 新しい画像が来たら内容を確認する
6. 必要なら手動 ROI や manual label を修正する
7. `保存` または `破棄` を押して次へ進む

### 11-3. 再学習データを準備する場合

1. 画像処理後に DeepScan やリアルタイムエンジンで manual label を付ける
2. プロジェクトを `保存` して ZIP を取得する
3. `再学習` ページで対象プロジェクトまたは ZIP を選ぶ
4. `ai_model_name` と現在の対象モデルが一致しているか確認する

## 12. 更新方法

開発者の更新を取り込む方法は 2 つあります。

### 12-1. ターミナルで更新する

```bash
git checkout AbyssEye-Neo
git pull --ff-only origin AbyssEye-Neo
```

### 12-2. Swagger から更新する

`AbyssEye` を起動済みなら、Swagger から `git pull` を実行することもできます。

手順:

1. ホーム画面で `Swagger` を開きます。
2. `POST /api/v1/dev/git/pull` を開きます。
3. `Try it out` を押します。
4. 必要なら body を次のように入力します。

```json
{
  "branch": "AbyssEye-Neo",
  "remote": "origin"
}
```

5. `Execute` を押します。

`branch` を省略した場合も、既定では `AbyssEye-Neo` を更新します。

必要なら依存関係を更新します。

```bash
source venv/bin/activate
pip install -r backend/requirements.txt
cd frontend
npm install
```

フロントエンドに変更が入っている場合は、取り込み後に再ビルドまたは再起動が必要です。

## 13. 困ったとき

- トップ画面でバックエンド接続エラーが出る
  バックエンドが起動していない可能性があります。起動手順を確認してください。

- 推論できない
  `モデル選択` でアクティブモデルが設定されているか確認してください。

- DeepScan が開けない
  対象画像の ROI 抽出や推論がまだ終わっていない可能性があります。

- 手動削除できない ROI がある
  削除できるのは手動追加した ROI のみです。

- 更新したのに見た目が変わらない
  フロントエンドを再起動していないか、build が古い可能性があります。

- `git pull --ff-only` や Swagger の `dev/git/pull` が止まる
  ローカルの未コミット変更や独自 commit がある可能性があります。必要に応じて変更を退避または commit してからやり直してください。

## 14. 補足

- 推論モデルを切り替えた場合、その後の推論やリアルタイム処理には新しいアクティブモデルが使われます。
- リアルタイム監視スクリプトは、監視先フォルダに TIFF が入る運用を前提としています。
- 再学習ページはパスワード保護されています。
